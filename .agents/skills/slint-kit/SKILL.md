# Consume Slint Kit

This skill describes the module API introduced in Slint Kit 0.7. Read the target application's dependency and build configuration before integrating it. Use matching `slint-kit` and `slint-kit-build` releases and Slint pinned to their supported version. Published 0.6 packages use the previous API; follow their matching documentation. The toolkit checkout is optional for registry consumers. [CHANGELOG.md](../../../CHANGELOG.md) lists the integration and behavior changes. Verify the selected release is published before resolving it from crates.io; local development uses matching source dependencies.

## Desktop and mobile targets

The components can be used in desktop Rust applications (macOS, Windows, Linux) and in Android/iOS applications through Slint’s mobile backends. See [platform setup](https://slint-kit.dev/guides/project-setup/#desktop-and-mobile-targets) and its [French version](https://slint-kit.dev/fr/guides/project-setup/#desktop-and-mobile-targets). Android needs `backend-android-activity-06`, a `cdylib` entry point and SDK/NDK tools; iOS uses winit/Skia and Xcode on macOS. Adapt desktop starter entry points and packaging to the target. Keep the same `@kit` imports, build helper and per-window `install`. Optional `native` file/directory dialogs return `SelectionOutcome::Failed(HostError::Unsupported)` on mobile. Verify touch, keyboard/IME and accessibility on target devices; desktop screenshots and headless tests do not qualify mobile devices.

## Wire the consumer

Merge these registry dependencies into the application’s `Cargo.toml`:

```toml
[dependencies]
slint-kit = "0.7"
slint = { version = "=1.18.1", default-features = false, features = ["std", "compat-1-18", "backend-winit", "renderer-skia", "accessibility"] }

[build-dependencies]
slint-kit-build = "0.7"
```

Use edition 2024 and Rust 1.92 or later. Preserve the app's chosen backend and renderer when compatible; the manifest above is a desktop example. Add `features = ["native"]` to `slint-kit` only when host services are needed.

In `build.rs`, compile through `slint-kit-build` so the `@kit` library and contract verification remain configured:

```rust
fn main() {
    slint_kit_build::compile("ui/app.slint").expect("compile application UI");
}
```

On Windows, require Slint Kit 0.7.1 or later: 0.7.0 incorrectly escapes canonical source paths. Both build helpers accept relative, absolute and canonical paths, including spaces and Unicode. For custom Slint compiler configuration, start with `slint_kit_build::config()` and pass it to `compile_with_config`; application include paths and library aliases are preserved. A minimal `ui/app.slint`:

```slint
import { KitButton, KitTextField } from "@kit";
export component App inherits Window {
    preferred-width: 360px;
    preferred-height: 180px;
    in-out property <string> name;
    callback save(string);
    VerticalLayout {
        padding: 24px; spacing: 16px; alignment: start;
        KitTextField { label: "Name"; text <=> root.name; }
        KitButton { text: "Save"; activated => { root.save(root.name); } }
    }
}
```

In `src/main.rs`, include the generated module and connect the application callback:

```rust
slint::include_modules!();

fn main() -> Result<(), slint::PlatformError> {
    let app = App::new()?;
    slint_kit::install(&app);
    app.on_save(|name| println!("Draft submitted: {name}"));
    app.run()
}
```

Run `cargo run`. Initialize form validation once per window before showing it. Set intrinsic options such as `required`, `pattern`, `min`, `max` and `step` on the control. Guard Rust submission with matching `FieldBinding::set_html_constraints(HtmlConstraints { ... })` rules before accepting a domain value; the example callback only logs the draft. See the [forms guide](https://slint-kit.dev/guides/forms/). Ordinary fields already include `label`, help and error presentation. `KitFieldLabel` is a composition primitive for custom skins; it is not needed to set a field label. Component catalogue examples export `Example` instead of `App`: use the `Example` entry point from the getting-started guide and remove callbacks from the previous example. Screenshots show the declared state; use the typed application guide for a complete interactive controller.

For local toolkit development, use `slint-kit = { path = "../slint-kit/crates/kit" }` and `slint-kit-build = { path = "../slint-kit/crates/kit-build" }` with paths adjusted to the checkout. The library files are bundled in the registry packages; consumers do not need a checkout.

The Slint language server does not read `build.rs`. For registry consumers, run `cargo vendor --locked target/slint-editor/vendor` from the workspace root, then map `kit` to the file `target/slint-editor/vendor/slint-kit-slint/ui/kit.slint` in VS Code's `slint.libraryPaths`, or pass `-L kit=target/slint-editor/vendor/slint-kit-slint/ui/kit.slint` through Zed's `lsp.slint.binary.arguments`. Vendoring copies all remote dependencies; refresh after lockfile changes or `cargo clean`. Check the vendor directory name when several kit versions are resolved. Local path dependencies are not vendored: point the editor at the checkout's `crates/kit-slint/ui/kit.slint` file using a workspace-relative path. Slint 1.18.1 resolves a bare alias as a file and suffixed imports by joining onto that path: one LSP alias cannot resolve both `@kit` and `@kit/fonts/...` or `@kit/icons/...`. Prioritize the root component import with the file mapping; supplemental imports remain valid in Cargo through module metadata but can show unresolved diagnostics in the language server. Do not switch application imports back to `@kit/kit.slint` to hide that editor limitation. Preserve existing editor settings and library aliases. See the editor setup guide for complete JSON examples.

## Preview and live-preview limits

Slint Kit 0.7.2 shows declarative selection options in pure-Slint editor and `slint-viewer` previews without Rust. This is a static presentation: filtering, generation checks and selection acceptance still require `install(&window)`. Single selection marks use the declared reference; multi-selection marks/chips and expanded accordion bodies need explicit `rows`/`chips` projections for an exact preview. Calendars need explicit `days` and `title`; typed fields need authored text for a static value. Use the Rust-backed browser demo or `cargo run` to exercise services. See the bilingual editor guide for the component-family matrix.

With Slint 1.18.1, do not set `SLINT_LIVE_PREVIEW`, even to `0` or an empty string: Slint's live-preview generator omits library global exports/implementations (slint-ui/slint#14812). Slint Kit reports this limitation before producing broken Rust. Remove assignments from `build.rs` and development scripts and rebuild. The `slint/live-preview` feature alone does not select that generator; `slint/mcp` and `SLINT_EMIT_DEBUG_INFO=1` remain usable for runtime debugging. The build helper follows Slint’s metadata default; enable inspection explicitly with that environment variable or `config().with_debug_info(true)` in test builds.

## Choose and compose

Choose components from the catalogue, then verify their public properties and typed callbacks against the resolved version. Read [the public exports](../../../crates/kit-slint/ui/kit.slint) to find current component names, then read the relevant source for properties and typed callback signatures. The public files are the maintained API reference; do not guess names from a web kit. [The showcase](../../../showcase/ui/forms-gallery.slint) and its [Rust field bindings](../../../showcase/src/form_fields.rs) demonstrate a complete consumer.

Keep accepted application values in Rust. `slint_kit` reexports the domain types and adapters: use enums for policies and states, `FieldBinding<T, E>` for typed draft/commit handling, and `Choices<K>` for stable keyed options. Give its `model()` to a component’s `options`, bind `selected` when needed, and resolve its typed `chosen` payload with `Choices::accept`. `SelectBinding` and `bind_select!` remain deprecated compatibility adapters for explicit controlled projections. Read [field.rs](../../../crates/kit-slint/src/field.rs) and [select.rs](../../../crates/kit-slint/src/select.rs) for their exact APIs; `Ownership::Controlled` still requires acknowledgment. Ordinary fields use `FieldSpec<T,E>` and the inherited `committed(FieldCommit)` contract instead of copying edited/commit/blur/cancel handlers. Use `KeyedModel<K,Row>` for host-owned collections and preserve stable keys through replacement. Keep incomplete drafts editable and let the native editor own caret, selection, undo and IME.

Text fields retain one native editor for selection, clipboard and history. Use their UTF-8 byte-offset selection functions and native `undo`/`redo`/`paste` forwarding instead of rewriting `text`. `has-focus` and `focus-observed` include the owned editing menu, so opening it does not commit a blur or close an inline editor. `take-focus()` and `blur()` close that menu explicitly. Use `TextContextMenu.disabled` for a host-owned menu and `KitStrings.text-menu-label` for its default accessible name. Follow the forms guide for Slint popup focus, accessibility-role and touch limitations.

Use `DecimalValue`, `Money` and explicit currency/locale/rounding rules for numeric domains. Use civil dates, local times and explicit time-zone resolution; never convert an ambiguous local time silently. Renderer positions and byte-channel projections do not replace validated domain values.

Pass `KitTheme` and `ControlSize` into composed controls, or assign `KitThemeContext.current` once per window (re-export the global from the main Slint file to set it from Rust). This is a default context, not a CSS ancestor cascade. A local component’s `theme` affects its known internal controls; application-supplied `@children` need explicit `theme: parent-component.theme` bindings. Keep neighboring regions independent. The built-in light and dark modes are `KitThemes.light` and `.dark`.

The kit ships one Tailwind-inspired presentation with `KitThemes.light` and `.dark`; no additional theme package is needed. It uses Lucide for built-in icon roles. `slint_kit_build::compile` registers `@kit`; `config_with_libraries(HashMap<String, PathBuf>)` preserves application aliases and reserves `kit`. Inter is optional: import `{ InterFont } from "@kit/fonts/inter.slint"` and set the Window's `default-font-family: InterFont.family`. Importing components alone does not embed Inter. The default themes do embed JetBrains Mono Regular (OFL 1.1) for `typography.family-monospace`; this named, registered font keeps code cells portable across native and WASM builds. A custom code font must be registered, monospaced and cover both the code alphabet and mask glyphs. The documentation examples explicitly choose Inter.

Use local presentation properties rather than partial recipe literals. `KitPressable` and buttons expose `corner-radius`, `padding-inline`, `padding-block`, `text-size`, and `text-weight`; text fields expose radius, paddings, text size and leading/trailing icons; `KitCard` and `KitSurface` expose radius and elevation. Preserve intrinsic layout and state resolution. Custom `text-size` values should include `theme.text-scale` when they must follow enlarged-text preferences. A custom theme must provide every field, including `shape`, `elevation`, `focus`, `typography`, `spacing`, `motion`, `icons`, and `geometry`; omitted Slint struct fields silently become zero or transparent. Prefer copying a shipped theme in Rust and changing individual fields.

When composing custom Pressable content, its padding is already applied to the insertion rectangle: center against the content dimensions rather than blindly using the lexical parent’s height or width. See the public KitButton implementation for leading/trailing placement.

Icons are `IconGlyph` values from named functions: `KitGlyphs.close()` for the kit's own glyphs, or `LucideIcons.trash()` after `import { LucideIcons } from "@kit/icons/lucide/all.slint";` (one file per Lucide category also exists; check names there, since Lucide renamed several Feather icons). Paint them with `KitIcon { glyph: ...; }` or `KitIconButton { glyph: ...; accessible-name: "..."; }`; there is no `IconKind` any more. Use `leading-icon` / `trailing-icon` directly on `KitButton` and text fields for ordinary icon-plus-text content, rather than rebuilding a Pressable. Built-in glyphs read `theme.icons` (`KitIconSet`): the built-in theme supplies Lucide. Distinguish these semantic roles from application-selected arbitrary Lucide icons. The [Lucide gallery](https://slint-kit.dev/components/icon/) generates import and integration snippets. Pass `ink` from the surrounding recipe. Icons are decorative by default; set `purpose: IconPurpose.informative` and a `label` only when no nearby text says what the icon means. Size follows `control-size` and `text-scale`; `stroke-mode: IconStroke.absolute` keeps a fixed stroke width. Never edit the generated Lucide files. `KitCard` and `KitHero` accept `LayoutSpace` inset and gap values. Choose `ControlWidth.fill` where the containing layout needs it. Build custom skins on the shared pressable, selection and dialog primitives so pointer, keyboard, focus and disabled behavior remain consistent. For larger screens, inspect the [layout wrappers](../../../crates/kit-slint/ui/layout.slint); for large collections, inspect [data components](../../../crates/kit-slint/ui/data.slint) and preserve model identity and virtualization.

The [display gallery](../../../showcase/ui/base-display.slint) and [its controller](../../../showcase/src/base_display.rs) show alerts, tooltips, toasts and progress. Mount one `KitTooltipLayer` as the final child of each window, provide its viewport size, and disable it while a modal or another screen hides its triggers. `KitTooltip` reports keyboard focus to that window-local layer. Bind `target-focused` to a KitButton/KitPressable’s `focus-visible`, so pointer activation does not open a keyboard hint. Keep toast lifetimes in Rust with `ToastQueue`; map `ToastInteraction.pointer` and `.focus` to separate `ToastPause` sources. Pause/resume must preserve the remaining lifetime. Keep the same `ToastBinding::model()` installed; incremental keyed insert/remove preserves surviving toast delegates and their focused controls across other queue changes.

`KitDrawer` fills its host viewport and anchors its bounded panel to the trailing edge. Mount it at the Window root after scrollable content; register each real field and preserve the exact opener in the focus registry. `KitAccordion` keeps the public single expansion default; the showcase demonstrates multiple expansion by default. Disclosure bodies remain mounted during their reduced-motion-aware height transition.

The [navigation gallery](../../../showcase/ui/base-navigation.slint) demonstrates keyed menus, tabs, notifications and a window-level modal drawer with a focus trap. Host controllers acknowledge activation with stable tokens and generation, own the selected content, skip disabled choices and restore focus when overlays close. Data views render finite viewports over `ModelRc` collections; do not materialize every UI delegate or use row position as identity. `KitVirtualTextView` virtualizes document lines and offers native editing of the selected line; use `KitTextArea` for a whole editable buffer.

`KitScrollArea` and virtualized data viewports reserve stable scrollbar gutters by default, including for hidden `as-needed` bars. Bind fitted content to `visible-width` / `visible-height`, rather than the outer rectangle. Use `overlay-scrollbars: true` on `KitScrollArea` only when its content independently protects trailing control edges.

`KitNotificationCenter` keeps the read action's slot stable using `mark-read-label` and `read-label`. A dismissed row disables its actions during a 150ms fade, then emits `dismiss-row` with the captured token and generation; reduced motion removes the delay. A changed identity cancels a pending dismissal. Keep popup placement and viewport bounds stable for the open session while the host acknowledges read, preview and dismissal actions.

`KitDateTimeField` and `KitZonedDateTimeField` accept host-localized labels/help and expose `editor-focused` plus `focus-observed(bool)`. `KitDatePicker`, `KitDateTimeField` and `KitZonedDateTimeField` share the text-field `commit-policy`: with the default `on-blur`, a valid typed value is accepted when focus leaves the whole control (every editor of a composed field), not only on Enter; do not require Enter in application flows. Preserve ambiguity context on `ambiguity-started()` and accept only the completed `ambiguity-chosen` action. `KitDatePicker` and `KitCalendar` expose calendar action names; `KitDataTable` and `KitContentList` expose `empty-label`, and `KitDataTable` also takes `sort-ascending-label`, `sort-descending-label` and `unnamed-row-label` for its accessible names. Labels do not change Rust parsing. The table's accessible tree is what Slint 1.18.1 offers (`table`, `button` or `text` headers, `list-item` rows, the active row named in the table label); do not promise cell-level navigation, and treat headless tests as contract proofs rather than screen-reader qualification. Column widths are a policy on each `TableColumn.width` (`ColumnWidth`: `sizing` fill or fixed, `basis`, `minimum`, `ceiling` unbounded or bounded, `maximum`, `resizable`), keyed by the column's token, never by its position; `ColumnWidth::default()` is the fill behaviour. Handle `resize-requested(token, width)` by storing the width for that column key and republishing the column with `sizing: fixed, basis: width`; the table never stores widths itself, and the request is already clamped to the column's bounds. Row cells are plain strings (`TableRow.cells`) or typed presentation cells (`TableRow.content`): build the latter in Rust from `CellContent::text`, `CellContent::badge(text, ui::Tone)` or `CellContent::check(CheckState, text)` with `table_cells(...)`, one per column in column order; `content` wins when a row carries both. A check cell's `text` is its accessible meaning in the host's words, badges and marks follow the column alignment, and the kit paints the cells inside the virtualized row because Slint 1.18.1 does not allow `@children` or slots in a repeated element; there is no caller-supplied cell template and no cell toggling. A `field` cell edits in place: `CellContent::field(text, FieldAccess)` or `CellContent::typed_field(key, &spec, Some(&value), FieldAccess)` with the `FieldSpec` installed under `key`; Left/Right move the cell cursor (`active-column`), Enter opens the one `KitTextField` of the table, Enter/Tab commit, Escape cancels, focus loss commits an acceptable draft, and the rejected message is in `edit-error`. Handle `cell-committed(row, column, generation, commit)` with `KeyedModel::cell_commits`, which fences the generation, then `spec.accept(commit)` and republish the row; a new generation closes an open editor without committing. Do not claim IME or screen-reader qualification from the headless tests.

For dates, use `DatePattern` to validate one explicit Gregorian date format and `DateNames` for localized names (`DateNames::french()` is included). Years are 1–9999; numeric input uses ASCII digits. HTML date inputs keep `YYYY-MM-DD`; custom localized entry combines a native `KitTextField` with the same Rust `DatePattern` and `DateConstraints` used by the calendar. Never try competing ambiguous orders or infer a century. `DateConstraints` validates bounds, unavailable weekdays and blackout intervals. `DateRangeController::with_rules` applies `DateRangeRules` to every day of a range and counts civil nights (same-day means zero); a rejected endpoint preserves the draft start. Set the calendar’s bounds, unavailable weekdays/ranges and `week-start` props; its instance owns navigation and projects the enabled previous/next actions through `CalendarController`. Localize month/weekday and action labels, and choose any of the seven `WeekStart` values. Read-only calendars browse without selecting. `DateSetController` stores multiple selected `CivilDate` keys; `grid_for_month` lets several calendars share one controller's constraints and selection.

`KitDialogSurface.tab-policy` defaults to `DialogTabPolicy.host`; `.native` lets Slint traverse the mounted controls. The host must disable every background focus target during the modal, including navigation composites/table `interactive: false` (`KitMenu`, `KitMenuBar`, `KitTabs`, `KitAccordion`, `KitCarousel`, `KitBreadcrumbs`, `KitPagination`), and ordinary buttons/fields through `disabled`/`FieldAccess.disabled`. A scrim does not block semantic accessibility actions. Disable custom children separately and restore the exact opener. Only topmost dialogs consume Escape/system Back; busy dialogs do not dismiss. Use `DialogHost<W,L,T>` from the [dialog composition guide](https://slint-kit.dev/guides/dialog-example/): declare typed `DialogLayerSpec` parents before descendants and `DialogFocusSpec` stable tokens/order, supply explicit `DialogHostPorts` setters, then forward `open`, `close`, `cycle` and actual `observe_focus` events. The adapter owns stack/registry, eligibility, descendant trap cleanup, exact opener restoration and slots→states→focus publication after borrows end. Bind each `FocusSlot.eligible` to the actual control’s disabled/access state. `DialogActivity::Busy(target)` keeps that action eligible for focus while busy; the surface consumes Escape and Back. Use `set_enabled` for changing target eligibility. These are surfaces inside the application window, never system modal windows. Persistent menus and tabs let system Back reach the overlay. Preserve a menu row’s focus during pointer-down rather than stealing it before activation.

Native file requests are asynchronous and return explicit cancellation, failure or unsupported outcomes. Read [host integration](../../../crates/kit-native/src/lib.rs) and [the showcase integration](../../../showcase/src/form_files.rs) before enabling pickers or drag and drop. Capability depends on the actual backend and target; exposing a DropArea alone does not prove external file-drop support.

Verify the target app builds, exercise its real callbacks and inspect its native rendering in light/dark themes, at 200% text and with keyboard navigation. Native screenshots are visual examples, not screen-reader, IME or external-drop qualification. [Announced and qualified targets](https://slint-kit.dev/guides/getting-started/) names the OS, backend and renderer behind each proof the kit publishes (full check on macOS, headless tests and clippy on Linux, build checks on Windows, native captures with winit and Skia on macOS); do not present a target as qualified beyond that, and report any qualification you do with the same names. Linux headless component/workspace tests and clippy passed on Ubuntu 24.04 (x86_64), testing backend/software renderer, at [59ece023](https://github.com/damione1/slint-kit/actions/runs/42769690387/job/129674322933) on 2026-11-10; this adds no native, IME or screen-reader qualification. To build the showcase, follow [Build the showcase](https://slint-kit.dev/guides/getting-started/); cloning is needed for that source application, not for installing the library. Preserve the toolkit's [GPL-3.0-or-later license](../../../LICENSE) for its code and bundled assets, along with dependency notices. Choose and document application-specific assets separately.

`KitAvatar` is static by default. Use `AvatarInteraction.action` with `activated`, `disabled` and a meaningful `accessible-name` for an actionable profile; do not wrap it in another button. `KitOtpField` keeps one native editor in boxed and `FieldDecoration.underlined` presentations. Its `slots` property supplies the default minimum/maximum validation lengths, and `pattern` defaults to `[0-9]*`; use `[A-Za-z0-9]*` and matching Rust `OtpRules::new(OtpLength, HtmlPattern)` for letters and digits. Both use complete-draft HTML patterns and UTF-16 length units. The existing `OtpValue::parse`/`OtpAlphabet` API remains available. For a read-only masked OTP view, set `input-type: InputType.password` and `access: FieldAccess.read-only`. Editable password undo can panic in Slint 1.18.1 after a shorter selection replacement; do not claim that path is qualified. OTP defaults to `TextLengthPolicy.limit`: reject any overlong native edit atomically, including paste and selection replacement; do not guess the replaced span from matching text. This intentionally differs from browser partial-paste behavior. The shared boundary counts UTF-16 units, while public `set-selection-offsets` uses UTF-8 byte offsets. An explicit `max-length` overrides the slot default; -1 disables the cap. Host assignments or reduced limits keep the fitting prefix. Slint 1.18.1 requires native undo before restoring rejected text to avoid stale undo offsets; refusal can discard undo/redo history and collapse selection to a safe common-prefix caret. In-limit edits preserve native history. Initialize form validation before showing strict inputs, which stay read-only until ready. `TextLengthPolicy.validate` opts back into validation-only and remains the default for other text fields. Do not claim native IME qualification from keyboard tests. Use `ValidationTiming.on-submit` when a partial code should remain visually neutral until acceptance. Optional formatting uses inherited `display-text` at rest and raw `text` while focused: `FG76657` is a seven-character value with `slots: 7` and pattern `[A-Z]{2}[0-9]{5}`, while `FG‑76657` is its host display projection. Do not count the separator as a slot or normalize pasted separators silently. `KitMaskedField` compiles `mask` (`#` ASCII digit, `A` ASCII letter, `*` ASCII alphanumeric, `\`-escaped literal; 1–256 tokens with at least one slot) through the shared HTML engine and bounded `MaskPattern` cache. It derives length bounds, full-value pattern and placeholder. Keep `TextLengthPolicy.validate` to preserve full host assignments, mask changes and native deletion/cut/undo/redo; an invalid draft stays visible and cannot commit. Ordinary ASCII key insertions and explicit paste are checked before insertion; native non-ASCII/IME paths without a public pre-insertion event are validated afterward without rewriting text. No automatic literal insertion or mask rollback. Nonempty masks remain read-only before install, including public paste/cut. `format-error`/`KitStrings.mask-format-message` expose malformed configuration; `FieldSpec::masked(MaskPattern::compile(...)?)` guards Rust acceptance. `KitTextField.validation-mask` is only the low-level prefix guard and does not derive its other constraints. Badges and stats accept optional decorative `leading-icon` glyphs.


`KitSegmentedControl.icons` takes `ChoiceIcon { token, glyph }` values keyed to unchanged `ChoiceRow` tokens. Set `columns: 2` for a two-column horizontal grid; horizontal arrows traverse reading order, RTL reverses each row, Up/Down step by `columns` across wrapped horizontal rows, and vertical groups keep Up/Down navigation. `KitCheckbox`, `KitSwitch` and `KitRadioGroup` activate with `Space` and reject `Enter` (`Return`) so enclosing forms can handle submission; `KitRadioGroup` navigates on both Up/Down and flow-aware Left/Right arrows. Choice and navigation composites expose configurable `wrap` (`true` by default on `KitRadioGroup`, `KitSegmentedControl`, `KitToggleGroup`, `KitMenu`, `KitMenuBar`, `KitTabs` and `KitCarousel`; `false` on `KitSelect`, `KitSelectTrigger`, `KitSelectSurface`, `KitSelectKeyboard`, `KitMultiSelect` and `KitCombobox`), `typeahead-timeout-ms` (default `700`, accepting spaces inside an active query and resetting on arrow/Home/End/PageUp/PageDown navigation), and `page-rows` (`viewport-height / row-height`, `0` until measured; unmeasured PageUp/PageDown are rejected) for `PageUp`/`PageDown`. Closed `KitSelect` triggers open on `Home`, `End` and printable typeahead; `KitTabs.activation` selects `TabActivation.manual` (default) or `.automatic`; `KitToggleGroup` adds `direction` and `flow`; `KitMenuBar`, `KitTabs` and `KitCarousel` inherit `flow: theme.direction`; and `KitCarousel` handles `LeftArrow`/`RightArrow` (mirrored in RTL) and `Home`/`End`. Keyboard activation fails closed without `install` and rejects missing, disabled or duplicate active tokens; keep generation checks in the owning controller. Read-only segments and switches render neutral state. Explicit slider track/fill/handle brushes apply when disabled too; bind them to access for a separate palette. A button with a single icon keeps its label centered in the whole control. Keypad width can shrink independently of key height at 200% text; use `activation-started()` for early feedback and the existing digit/delete/confirm callbacks for accepted actions.

For draggable controls inside a scrolling viewport, set `KitScrollArea.pan-policy: children-first`. A child that claims Down keeps its gesture; background/text drags pan directly without inertia, while wheel/bars/focus reveal remain available. The default `native` keeps Slint arbitration. This presentation enum is exported by `@kit`.

## Module services and callback ownership

Call `slint_kit::install(&window)` once per window, before showing it. Build with `slint_kit_build::compile`; the build helper exports the globals needed by that installer. Do not repeat globals or per-component callback names on the application root. Import shared types through `@kit`; icon/font source files remain supplemental imports.
