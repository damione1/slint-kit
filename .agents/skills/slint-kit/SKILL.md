# Consume Slint Kit

This skill describes the module API introduced in Slint Kit 0.7. Read the target application's dependency and build configuration before integrating it. Use matching `slint-kit` and `slint-kit-build` releases and Slint pinned to their supported version. Published 0.6 packages use the previous API; follow their matching documentation. The toolkit checkout is optional for registry consumers. [CHANGELOG.md](../../../CHANGELOG.md) lists the integration and behavior changes. Verify the selected release is published before resolving it from crates.io; local development uses matching source dependencies.

## Desktop and mobile targets

The components can be used in desktop Rust applications (macOS, Windows, Linux) and in Android/iOS applications through Slint’s mobile backends. See [platform setup](https://slint-kit.dev/guides/project-setup/#desktop-and-mobile-targets) and its [French version](https://slint-kit.dev/fr/guides/project-setup/#desktop-and-mobile-targets). Android needs `backend-android-activity-06`, a `cdylib` entry point and SDK/NDK tools; iOS uses winit/Skia and Xcode on macOS. Adapt desktop starter entry points and packaging to the target. Keep the same `@kit` imports, build helper and per-window `install`. Optional `native` file/directory dialogs return `SelectionOutcome::Failed(HostError::Unsupported)` on mobile. Verify touch, keyboard/IME and accessibility on target devices; desktop screenshots and headless tests do not qualify mobile devices.

## Wire the consumer

For a new application, the source CLI is installed with `cargo install --git https://github.com/damione1/slint-kit --branch develop slint-kit-cli --locked`. Run `slint-kit new my-app`, or add `--web` for desktop plus WASM preview; then run Cargo inside the new directory. Existing paths are never overwritten. `--name my-app` separates a portable Cargo name from a directory containing spaces or Unicode. The generated manifest/build helper share the component-download template; the Rust factory installs once and connects a weak-window action. See the bilingual project-setup guide for browser tooling and renderer differences. No CLI registry publication is assumed.

Merge these registry dependencies into the application’s `Cargo.toml`:

```toml
[dependencies]
slint-kit = "0.7"
slint = { version = "=1.18.1", default-features = false, features = ["std", "compat-1-18", "backend-winit", "renderer-skia", "accessibility"] }

[build-dependencies]
slint-kit-build = "0.7"
```

Use edition 2024 and Rust 1.92 or later. Preserve the app's chosen backend and renderer when compatible; the manifest above is a desktop example. Add `features = ["native"]` to `slint-kit` only when host services are needed.

In `build.rs`, compile through `slint-kit-build` so the `@kit` library and contract verification remain configured:

```rust
fn main() {
    slint_kit_build::compile("ui/app.slint").expect("compile application UI");
}
```

On Windows, require Slint Kit 0.7.1 or later: 0.7.0 incorrectly escapes canonical source paths. Both build helpers accept relative, absolute and canonical paths, including spaces and Unicode. For custom Slint compiler configuration, start with `slint_kit_build::config()` and pass it to `compile_with_config`; application include paths and library aliases are preserved. A minimal `ui/app.slint`:

```slint
import { KitButton, KitTextField } from "@kit";
export component App inherits Window {
    preferred-width: 360px;
    preferred-height: 180px;
    in-out property <string> name;
    callback save(string);
    VerticalLayout {
        padding: 24px; spacing: 16px; alignment: start;
        KitTextField { label: "Name"; text <=> root.name; }
        KitButton { text: "Save"; activated => { root.save(root.name); } }
    }
}
```

In `src/main.rs`, include the generated module and connect the application callback:

```rust
slint::include_modules!();

fn main() -> Result<(), slint::PlatformError> {
    let app = App::new()?;
    slint_kit::install(&app);
    app.on_save(|name| println!("Draft submitted: {name}"));
    app.run()
}
```

Run `cargo run`. Initialize form validation once per window before showing it. Set intrinsic options such as `required`, `pattern`, `min`, `max` and `step` on the control. Guard Rust submission with matching `FieldBinding::set_html_constraints(HtmlConstraints { ... })` rules before accepting a domain value; the example callback only logs the draft. See the [forms guide](https://slint-kit.dev/guides/forms/). Ordinary fields already include `label`, help and error presentation. `KitFieldLabel` is a composition primitive for custom skins; it is not needed to set a field label. Component catalogue examples export `Example` instead of `App`: use the `Example` entry point from the getting-started guide and remove callbacks from the previous example. Screenshots show the declared state; use the typed application guide for a complete interactive controller.

For local toolkit development, use `slint-kit = { path = "../slint-kit/crates/kit" }` and `slint-kit-build = { path = "../slint-kit/crates/kit-build" }` with paths adjusted to the checkout. The library files are bundled in the registry packages; consumers do not need a checkout.

The Slint language server does not read `build.rs`. For registry consumers, run `cargo vendor --locked target/slint-editor/vendor` from the workspace root, then map `kit` to the file `target/slint-editor/vendor/slint-kit-slint/ui/kit.slint` in VS Code's `slint.libraryPaths`, or pass `-L kit=target/slint-editor/vendor/slint-kit-slint/ui/kit.slint` through Zed's `lsp.slint.binary.arguments`. Vendoring copies all remote dependencies; refresh after lockfile changes or `cargo clean`. Check the vendor directory name when several kit versions are resolved. Local path dependencies are not vendored: point the editor at the checkout's `crates/kit-slint/ui/kit.slint` file using a workspace-relative path. Slint 1.18.1 resolves a bare alias as a file and suffixed imports by joining onto that path: one LSP alias cannot resolve both `@kit` and `@kit/fonts/...` or `@kit/icons/...`. Prioritize the root component import with the file mapping; supplemental imports remain valid in Cargo through module metadata but can show unresolved diagnostics in the language server. Do not switch application imports back to `@kit/kit.slint` to hide that editor limitation. Preserve existing editor settings and library aliases. See the editor setup guide for complete JSON examples.

## Preview and live-preview limits

Slint Kit 0.7.2 shows declarative selection options in pure-Slint editor and `slint-viewer` previews without Rust. This is a static presentation: filtering, generation checks and selection acceptance still require `install(&window)`. Single selection marks use the declared reference; multi-selection marks/chips and expanded accordion bodies need explicit `rows`/`choice-rows`/`chips` projections for an exact preview. Calendars need explicit `days` and `title`; typed fields need authored text for a static value. Use the Rust-backed browser demo or `cargo run` to exercise services. See the bilingual editor guide for the component-family matrix.

With Slint 1.18.1, do not set `SLINT_LIVE_PREVIEW`, even to `0` or an empty string: Slint's live-preview generator omits library global exports/implementations (slint-ui/slint#14812). Slint Kit reports this limitation before producing broken Rust. Remove assignments from `build.rs` and development scripts and rebuild. The `slint/live-preview` feature alone does not select that generator; `slint/mcp` and `SLINT_EMIT_DEBUG_INFO=1` remain usable for runtime debugging. The build helper follows Slint’s metadata default; enable inspection explicitly with that environment variable or `config().with_debug_info(true)` in test builds.

A changed `.slint` file does not reach a running application: use the editor preview or `slint-viewer` for static layout and `cargo run` for behavior backed by `slint_kit::install`. Use `cargo check` for quick Rust feedback. The development loop guide lists measured build times; do not quote build times that were not measured.

## Choose and compose

Choose components from the catalogue, then verify their public properties and typed callbacks against the resolved version. Read [the public exports](../../../crates/kit-slint/ui/kit.slint) to find current component names, then read the relevant source for properties and typed callback signatures. The public files are the maintained API reference; do not guess names from a web kit. [The showcase](../../../showcase/ui/forms-gallery.slint) and its [Rust field bindings](../../../showcase/src/form_fields.rs) demonstrate a complete consumer.

Keep accepted application values in Rust. `slint_kit` reexports the domain types and adapters: use enums for policies and states, `FieldBinding<T, E>` for typed draft/commit handling, and `Choices<K>` for stable keyed options. Give its `model()` to a component’s `options`, bind `selected` when needed, and resolve its typed `chosen` payload with `Choices::accept`. `SelectBinding` and `bind_select!` remain deprecated compatibility adapters for explicit controlled projections. Read [field.rs](../../../crates/kit-slint/src/field.rs) and [select.rs](../../../crates/kit-slint/src/select.rs) for their exact APIs; `Ownership::Controlled` still requires acknowledgment. Ordinary fields use `FieldSpec<T,E>` and the inherited `committed(FieldCommit)` contract instead of copying edited/commit/blur/cancel handlers. For state shared across screens, declare one Slint `global` per domain and keep a `Store<T>` in Rust: `store.observe(...)` projects the value into the global for each window (`as_weak`), `store.update(...)` writes it, and `store.remote()` gives a `Send` handle whose `update`/`set` run on the UI thread via `invoke_from_event_loop`. For network calls started from a callback, use `kit::spawn(&app, future, |app, result| ...)` (the window arrives upgraded, so no `as_weak`) or a `Latest` per request source: `latest.load(&app, future, |app, state: Loading<T, E>| ...)` reports loading, ready or failed and drops stale responses; no runtime is imposed (futures run through `slint::spawn_local`, so wrap tokio-bound futures with `async_compat::Compat`). For screen navigation, declare the screens as one route enum (variants may carry the parameters) and keep a `Router<R>` in Rust: `router.push/pop/replace` change the stack, `router.observe(...)` projects `navigation.change().into()`, the route (one exhaustive `match` to a Slint enum, no wildcard) and `navigation.can_go_back()` into the window. In Slint, one `KitScreen { active: root.route == Screen.x; change: root.change; }` per route inside `KitRouter { can-go-back: ...; back => { ... } }`; Escape and the system back key call `back()` while a screen is behind the current one and are ignored under an open modal layer. Use `KeyedModel<K,Row>` for host-owned collections and preserve stable keys through replacement. Keep incomplete drafts editable and let the native editor own caret, selection, undo and IME.

For composed text fields, `show-description: false` hides only the built-in helper row; keep `description` populated so the native editor retains its accessible help. DatePicker uses this when rendering help outside its editor.

Text fields retain one native editor for selection, clipboard and history. Use their UTF-8 byte-offset selection functions and native `undo`/`redo`/`paste` forwarding instead of rewriting `text`. `has-focus` and `focus-observed` include the owned editing menu, so opening it does not commit a blur or close an inline editor. `take-focus()` and `blur()` close that menu explicitly. Use `TextContextMenu.disabled` for a host-owned menu and `KitStrings.text-menu-label` for its default accessible name. Follow the forms guide for Slint popup focus, accessibility-role and touch limitations.

Use `DecimalValue`, `Money` and explicit currency/NumberSyntax/rounding rules for numeric domains. For durations use `FieldSpec::duration(DurationUnit::Seconds, rules) -> DurationFieldSpec` with an explicit `Milliseconds`, `Seconds`, `Minutes` or `Hours` unit matching the widget suffix and min/max/step quantity. Decimal text `5` in seconds stores 5000 ms; `5` in minutes stores 300000 ms. `accept` returns the parsed DurationValue; keep it. For loading/acknowledgement, handle `format(&value) -> Result<String, ParseIssue>` before updating the UI: inverse conversion through `DurationValue::quantity(unit)` must be exact and within configured scale/bounds. Sub-millisecond input or recurring/overly precise output returns ScaleExceeded, overflow returns Overflow; no silent rounding. Clock text such as 01:30 is unsupported. Other FieldSpec formatters remain infallible. `KitMoneyField` is a decimal visual alias; `FieldSpec::money(currency, rules)` attaches currency and enforces the supplied DecimalRules without deriving scale from CurrencyMetadata. `FieldSpec::money_in(metadata, syntax, sign, bounds)` derives the scale from the currency (extra decimals give ScaleExceeded) and shows symbol and grouping at rest; `CurrencyMetadata::iso(&code)` gives the ISO 4217 scale and a customary symbol for common currencies (None if unlisted) and `CurrencyMetadata::new(code, symbol, scale)` builds any other. The application chooses business rounding; `Money::format(&metadata, syntax, rounding)` checks currency and provides grouped symbol display with explicit metadata scale/rounding. Prefix/suffix labels impose no currency rule. Use civil dates, local times and explicit time-zone resolution; never convert an ambiguous local time silently. Renderer positions and byte-channel projections do not replace validated domain values.

Pass `KitTheme` and `ControlSize` into composed controls, or assign `KitThemeContext.current` once per window (re-export the global from the main Slint file to set it from Rust). This is a default context, not a CSS ancestor cascade. A local component’s `theme` affects its known internal controls; application-supplied `@children` need explicit `theme: parent-component.theme` bindings. Keep neighboring regions independent. The built-in light and dark modes are `KitThemes.light` and `.dark`.

The kit ships one Tailwind-inspired presentation with `KitThemes.light` and `.dark`; no additional theme package is needed. It uses Lucide for built-in icon roles. `slint_kit_build::compile` registers `@kit`; `config_with_libraries(HashMap<String, PathBuf>)` preserves application aliases and reserves `kit`. Inter is optional: import `{ InterFont } from "@kit/fonts/inter.slint"` and set the Window's `default-font-family: InterFont.family`. Importing components alone does not embed Inter. The default themes do embed JetBrains Mono Regular (OFL 1.1) for `typography.family-monospace`; this named, registered font keeps code cells portable across native and WASM builds. A custom code font must be registered, monospaced and cover both the code alphabet and mask glyphs. The documentation examples explicitly choose Inter.

Use local presentation properties rather than partial recipe literals. `KitPressable` and buttons expose `corner-radius`, `padding-inline`, `padding-block`, `text-size`, and `text-weight`; text fields expose radius, paddings, text size and leading/trailing icons; `KitCard` and `KitSurface` expose radius and elevation. Preserve intrinsic layout and state resolution. Custom `text-size` values should include `theme.text-scale` when they must follow enlarged-text preferences. A custom theme must provide every field, including `shape`, `elevation`, `focus`, `typography`, `spacing`, `motion`, `icons`, and `geometry`; omitted Slint struct fields silently become zero or transparent. Prefer copying a shipped theme in Rust and changing individual fields.

When composing custom Pressable content, its padding is already applied to the insertion rectangle: center against the content dimensions rather than blindly using the lexical parent’s height or width. See the public KitButton implementation for leading/trailing placement.

Icons are `IconGlyph` values from named functions: `KitGlyphs.close()` for the kit's own glyphs, or `LucideIcons.trash()` after `import { LucideIcons } from "@kit/icons/lucide/all.slint";` (one file per Lucide category also exists; check names there, since Lucide renamed several Feather icons). Paint them with `KitIcon { glyph: ...; }` or `KitIconButton { glyph: ...; accessible-name: "..."; }`; there is no `IconKind` any more. Use `leading-icon` / `trailing-icon` directly on `KitButton` and text fields for ordinary icon-plus-text content, rather than rebuilding a Pressable. Built-in glyphs read `theme.icons` (`KitIconSet`): the built-in theme supplies Lucide. Distinguish these semantic roles from application-selected arbitrary Lucide icons. The [Lucide gallery](https://slint-kit.dev/components/icon/) generates import and integration snippets. Pass `ink` from the surrounding recipe. Icons are decorative by default; set `purpose: IconPurpose.informative` and a `label` only when no nearby text says what the icon means. Size follows `control-size` and `text-scale`; `stroke-mode: IconStroke.absolute` keeps a fixed stroke width. Never edit the generated Lucide files. `KitCard` and `KitHero` accept `LayoutSpace` inset and gap values. Choose `ControlWidth.fill` where the containing layout needs it. Build custom skins on the shared pressable, selection and dialog primitives so pointer, keyboard, focus and disabled behavior remain consistent. For larger screens, inspect the [layout wrappers](../../../crates/kit-slint/ui/layout.slint); for large collections, inspect [data components](../../../crates/kit-slint/ui/data.slint) and preserve model identity and virtualization.

The [display gallery](../../../showcase/ui/base-display.slint) and [its controller](../../../showcase/src/base_display.rs) show alerts, tooltips, toasts and progress. Mount one `KitTooltipLayer` as the final child of each window, provide its viewport size, and disable it while a modal or another screen hides its triggers. `KitTooltip` reports keyboard focus to that window-local layer. Set `placement: TooltipPlacement.below|above|left|right` (default `auto`) for the keyboard tip, and set the same text as `description` on the wrapped KitButton/KitIconButton so screen readers hear it; without an enabled layer the native hover tip stays visible. The native hover delay and offset are not configurable. Bind `target-focused` to a KitButton/KitPressable’s `focus-visible`, so pointer activation does not open a keyboard hint. Keep toast lifetimes in Rust with `ToastQueue`; map `ToastInteraction.pointer` and `.focus` to separate `ToastPause` sources. Pause/resume must preserve the remaining lifetime. Keep the same `ToastBinding::model()` installed; incremental keyed insert/remove preserves surviving toast delegates and their focused controls across other queue changes.

`ToastBinding` schedules only the next unpaused timed expiry with a single-shot timer. Empty, persistent-only and fully paused queues do not wake the event loop. Push, dismissal, pause changes and expiry recompute the next delay; releasing one pause source does not override the other. Custom runtime adapters can call `ToastQueue::next_timeout(now)` using the same injected monotonic clock as `advance(now)`: it returns the remaining delay, `None` when nothing is running, or zero for an overdue record. Reading it does not mutate the queue; call `advance` to remove expired records. The timer closure retains only weak binding state, and dropping the last binding stops it even if its projected model survives.

Keep the ToastId returned by ToastBinding::push for dismiss_id; visual tokens are not queue IDs. on_closed replaces the prior observer and reports Expired/Dismissed/Action/Evicted/Cleared with a clone of the typed action (T: Clone remains required). The model/timer are updated before callbacks with no held binding borrow; reentrant mutations survive, and Action closure precedes the business handler once. update(id, view, lifetime) preserves ID/token/action and independent pauses, restarts duration and returns false for absent/expired entries without resurrection; a simple update emits no close event. Persistent avoids timeout, not capacity eviction or explicit removal. clear/len/is_empty are Rust binding APIs, not Slint props. Capture a weak window in UI observers; the weak timer/drop behavior is unchanged. Core breaking returns require consuming ToastChange.result and .closed (push/set_paused/update), or Vec<ToastClosed<T>> from advance/clear, preserving full payload/reason including expirations before eviction; binding push still returns ToastId.

`KitDrawer` fills its host viewport and anchors its bounded panel to the edge chosen by `side: DrawerSide` (`start`, `end` by default, `top`, `bottom`; `start` and `end` follow the theme direction, `panel-width` sizes the side panels and `panel-height` the top and bottom ones). Its close button requests `CloseReason.close-button`; map it to `DismissReason::CloseButton`, and keep `Programmatic` for closes your host requests. Mount it at the Window root after scrollable content; register each real field and preserve the exact opener in the focus registry. `KitAccordion` keeps the public single expansion default; the showcase demonstrates multiple expansion by default. Disclosure bodies remain mounted during their reduced-motion-aware height transition.

`KitCollapse` is standalone by default (`expanded`). For accordion-style sections with arbitrary children, give sibling `KitCollapse` a distinct `value: int` and bind `group-value <=> shared` on each: one section is open at a time, `collapsible: false` keeps one always open, and `open` reports the disclosed state. `KitAccordion` shows only an option description per section.

`KitMenu.items` (one `MenuItem` per `options` entry, same order) adds `kind: MenuItemKind` (`action`, `checkbox`, `radio`, `separator`, `group`), `leading-icon`, `shortcut`, `destructive` and `checked` to menu rows; mark separator and group options `disabled`, toggle `checked` yourself in `chosen`, and tune `max-natural-height`. Submenus are not provided.

`KitSelect.items` and `KitCombobox.items` (one `OptionItem` per decorated option, matched by `token`; a missing token is a plain option) add `kind: OptionItemKind` (`option`, `group`, `separator`), `leading-icon` and `trailing-text` to option rows; mark group and separator options `disabled` so navigation skips them. `KitSelect.clearable` shows a clear button (`clear-label`) that empties `selected` under `Ownership.local` and always emits `cleared()`. Filtering stays lowercase substring matching: for accent-insensitive or custom matching, filter in the host and pass `options`.

`KitPopover` is a trigger button (`text`, `intent`, `leading-icon`, `trailing-icon`) that opens an anchored panel holding its children; `KitDropdownMenu` is the same trigger opening a `KitMenu` of `options`, with `chosen(OptionRow)`. Both place the panel below the trigger, or above it when there is more room, and keep it inside the window, like the field popups. An outside press (a press on the trigger included) or Escape closes it; Down Arrow on the trigger opens it; `show()` and `dismiss(CloseReason)` drive it from code. `dismissed(CloseReason)` reports `escape`, `programmatic` (a choice or `dismiss`), `trigger-toggle` (trigger activated by keyboard or assistive action while open) or `host-closed` (an outside press or other native closure). Escape and `dismiss` return focus to the trigger. Slint forbids reading or calling an element of a popup from outside it, so react to panel content through its callbacks and `changed` handlers. Set `modal-layer` inside a modal. A right-click context menu and a collapsible application sidebar are not provided.

The [navigation gallery](../../../showcase/ui/base-navigation.slint) demonstrates keyed menus, tabs, notifications and a window-level modal drawer with a focus trap. Host controllers acknowledge activation with stable tokens and generation, own the selected content, skip disabled choices and restore focus when overlays close. Data views render finite viewports over `ModelRc` collections; do not materialize every UI delegate or use row position as identity. `KitVirtualTextView` virtualizes document lines and offers native editing of the selected line; use `KitTextArea` for a whole editable buffer. Its native editor/Save/Copy require TextViewAccess.edit-line and an active-index within current lines, including after model shrink/clear. Captured token/generation actions reject stale identities; Copy uses the current draft and returns editor focus. Read-only keeps the footer hidden. `font: TextViewFont.monospace` and `show-line-numbers` set typeface and gutter; Ctrl/Cmd+C and `copy-active-line()` copy the stored line text in any access mode, without moving focus, and emit `copy-line-text(token, generation, text)`. Validate callbacks with KeyedModel.accept/update_active/bind_active; never derive tokens from row indices or displayed line numbers.

`KitScrollArea` and virtualized data viewports reserve stable scrollbar gutters by default, including for hidden `as-needed` bars. Bind fitted content to `visible-width` / `visible-height`, rather than the outer rectangle. Use `overlay-scrollbars: true` on `KitScrollArea` only when its content independently protects trailing control edges. For read-only content that keyboard users must scroll, set `KitScrollArea.focusable: true` and a `label` (tab stop, inset focus ring; arrows, Page keys, Space, Home/End). `axes: ScrollAxes.horizontal|both` adds horizontal scrolling; `scroll-to-end()`, `at-start`, `at-end` and `edge-reached(ScrollEdge)` support infinite loading and scroll shadows. `ScrollAxes` and `ScrollEdge` are presentation enums exported by `@kit`.

`KitNotificationCenter` keeps the read action's slot stable using `mark-read-label` and `read-label`. A dismissed row disables its actions during a 150ms fade, then emits `dismiss-row` with the captured token and generation; reduced motion removes the delay. A changed identity cancels a pending dismissal. Unread rows append `unread-label` (default "Unread") to their accessible name and expose the description. To focus a row that is not mounted in a large (virtual) list, set `focus-token`, `focus-index` (for example `KeyedModel::index_of`) and bump `focus-request`; the list scrolls the row into view and focuses it. Keep popup placement and viewport bounds stable for the open session while the host acknowledges read, preview and dismissal actions.

Temporal host snapshots initialize the accepted baseline and idle text after install, including later-mounted controls: DateField accepted-date ({} absence), MonthField accepted-year/accepted-month (both0 absence), YearField accepted-year (0 absence), IsoWeekField accepted-week-year/accepted-week (both0 absence). These properties are in-out: a Local commit writes the parsed typed value back (absence writes {} or zeros; use <=> to share it, a one-way binding is replaced by the first write); Controlled never writes them, so guard Rust commits with the matching FieldSpec, retain the parsed value and assign the property to acknowledge. Invalid typed values and partial month/week pairs are ignored, never cleared. KitTimeField accepted-time is now in-out LocalTimeValue {present,time}; KitTimePicker accepted-time is in-out LocalTimeValue. Migrate every former bare LocalTimeView assignment/binding to {present:true,time:value}; {} or present:false is absence, while {present:true,time:{}} is midnight. TimePicker emits chosen(LocalTimeView) / cleared() and preserves committed(FieldCommit); Local updates its model, Controlled proposes and waits for the complete wrapper assignment. DateTime accepted-value is an atomic LocalDateTimeView ({} absence): host load/update/clear synchronizes the pair, chosen/cleared is Local publication or Controlled proposal acknowledged by a whole-model assignment. No half-pair acceptance or duplicate unchanged Enter/blur proposal. Host updates acknowledge baselines while preserving focused native drafts/caret/selection/undo; blur/cancel reconcile through ownership. An explicit initial draft, even empty, is preserved. acknowledge(FieldValue) alone only changes the native baseline, not the typed host model. Installed temporal quickstarts load typed values without authored text; catalogue text is explicitly static preview content, not service evidence. No native IME/AT qualification follows from headless checks.
Date/time localisation: KitTimePicker has hours-label/minutes-label/seconds-label, increase-template/decrease-template ({label} placeholder), placeholder and description; KitDatePicker/KitDateRangePicker forward unavailable-label and navigation-help; the four temporal composites forward required/underflow/overflow/step/bad-input messages; KitZonedDateTimeField adds ambiguous/nonexistent/resolved/resolve-prompt/invalid-zone messages; KitDateTimeField and KitZonedDateTimeField add time-placeholder. Defaults come from KitStrings (time-*, calendar-unavailable-label, calendar-navigation-help, time-zone-*). AM/PM markers are not localisable.

KitToastHost.take-focus() (and KitToast.take-focus()) focus the first toast's action, else its dismiss button, for an application-defined hotkey such as F8; the kit binds no key.

KitTabs is a horizontal header: Left/Right follows flow, Home/End navigate, Enter/Space activate. Up/Down, pages, Escape, modified chords and (by default) printable shortcuts reach the host. Opt in with typeahead-enabled; tab-width: ControlWidth.fill shares the strip equally and elides labels (default intrinsic scrolls); automatic activation also proposes optional prefix results. KitTabPanel composes KitStack: bind state to tabs.state and tab to Choices::selection(&DomainKey) from the same source. Never derive panel identity from a row index. Group panels in a KitStack with gap:none, pass theme to supplied children, and keep their own access policies. Inactive panels collapse while retaining native editors and undo. tab-stop defaults false for direct child traversal; true adds a static-content scope stop, and take-focus explicitly focuses that active scope. No background refocus or native tab-to-panel identifier relation is promised. For a static editor preview, author an available SelectState with positive generation and matching selected/tab references; ordinary runtime use needs install. These additions require the matching source kit until a later package release.

`KitSelect`, `KitCombobox` and `KitMultiSelect` open and close from code with `open()` and `close()` and report the state through the read-only `is-open`; `open()` does nothing while the control is read-only or disabled and does not emit `open-requested()`. `KitMultiSelect` emits `limit-reached(OptionRow)` when an addition is refused at `selection-limit` and exposes `at-limit`; selected tokens whose option was replaced no longer count against the limit.
